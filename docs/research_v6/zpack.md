# ZPack: три эксперимента для памяти и времени

## Зачем это нужно

Обучение Soup уже меняет поведение модели только за счёт наших Triton-операций. ZPack добавляет
три отдельные экспериментальные настройки. Они нужны для измерения на Tesla T4. В обычном запуске
все три настройки выключены, и старый путь обучения остаётся основным.

Важная граница: локальная машина Mac не имеет CUDA GPU. Написанные здесь CUDA-тесты на ней не
запускались. Значения экономии памяти и времени ниже — **ОЦЕНКИ**, а не результаты этих изменений.

## Что меняет каждая настройка

### 1. Повторный расчёт внимания

Переменная `SOUP_X_ATTN_CKPT` работает только в packed-ветке модели, когда в batch есть padding.
Она включает штатный механизм PyTorch checkpoint: промежуточные значения не хранятся до backward,
а повторно считаются при вычислении градиента. Состояние генератора случайных чисел сохраняется,
поэтому dropout должен использовать ту же маску.

- `SOUP_X_ATTN_CKPT=1` повторно считает весь путь внимания: LoRA-проекции q/k/v, padded-раскладку,
  RoPE, attention, gather и выходную проекцию.
- `SOUP_X_ATTN_CKPT=2` повторно считает только интерфейс attention, в котором находятся повторение
  K/V и SDPA.
- Любое другое значение выключает checkpoint.

**ОЦЕНКА:** вариант 1 может освободить около 1 070 МиБ на пиковом batch за примерно 2,4 с.
Вариант 2 может освободить около 504 МиБ за примерно 0,95 с. На batch без padding эта ветка
checkpoint не вызывается.

Это наш checkpoint, отдельный от настройки `gradient_checkpointing` в Soup.

### 2. Точное восстановление второй residual-суммы

`SOUP_X_EXACT_RESID=1` меняет сохранение только для сложения выхода MLP со следующим residual.
Вместо fp32-суммы в autograd-контексте остаются fp32 residual и fp16 выход MLP. В backward Triton
восстанавливает ту же сумму как `residual + delta.float()`. Если типы или формы не подходят,
используется прежний путь с сохранённой суммой. При выключенной настройке первый residual-add
остаётся без изменений.

**ОЦЕНКА:** около 168 МиБ экономии при 2 048 токенах, без заметного времени на дополнительный
расчёт. Равенство результата и градиентов проверяется CUDA-тестом побитовым сравнением; он
локально не запускался.

### 3. Меньше вариантов Triton-компиляции

`SOUP_X_MERGE_VARIANTS=1` включает три изменения, которые должны уменьшить число вариантов ядер:

- RoPE не специализирует ядро по длине последовательности.
- Chunked CE использует одно значение `WRITE_GRAD` на все чанки данного запуска.
- Backward add+RMSNorm использует один вариант `HAS_DSUM`; отсутствие второй суммы отмечается
  нулевым шагом чтения.

**ОЦЕНКА:** текущая компиляция занимает около 4,7 с внутри первого шага; ожидается, что часть
этого времени уйдёт. Значение обучения не должно меняться. Реальный выигрыш устанавливается
только парным измерением.

Все настройки независимы. В строке `all` скрипт включает attention checkpoint уровня 1,
точное восстановление residual и объединение вариантов.

## Изменённые файлы

- `solution/layer_tail.py` — подключает два режима checkpoint в packed-внимании и передаёт флаг
  точного residual только для MLP-сложения.
- `solution/add_rmsnorm.py` — сохраняет fp16-слагаемое для точного восстановления и объединяет
  вариант backward при включённой настройке компиляции.
- `solution/rope.py` — при объединении вариантов убирает специализацию по `seq`.
- `solution/ce_loss.py` — при объединении вариантов использует единое значение `WRITE_GRAD`.
- `solution/test_attention_checkpoint.py` — сравнивает обычный и checkpoint-пути, включая dropout,
  fp16/fp32 и backward на нечётной длине.
- `solution/test_exact_resid.py` — сравнивает выходы и градиенты для обычного и точного хранения,
  включая неподходящий dtype, который должен откатиться на обычный путь.
- `solution/test_merge_variants.py` — сравнивает RoPE, CE и residual backward с настройкой слияния
  и без неё.
- `scripts/t4_exp.sh` — запускает CUDA-тесты, матрицу A-B-A-B для публичных строк и длинных строк,
  а затем диагностику T4. Файлы запусков внутри репозитория находятся в `runs_exp/`; диагностика
  также пишет временные файлы вне checkout.

`solution/__init__.py` не изменён: новых Triton-ядер не добавлено, применяются существующие.
`solution/head_patch.py` прочитан; его менять для этих трёх опытов не требуется.

## Запуск на T4

Сначала один раз подготовьте среду и данные:

~~~bash
bash scripts/kaggle_1_tests.sh
bash scripts/t4_exp.sh
~~~

Скрипт выполнит для каждого набора данных и каждого варианта четыре отдельных прогона
`A1 → B1 → A2 → B2`. В A все `SOUP_X_*` настройки сняты. В B включён ровно выбранный вариант.
После каждой команды сохраняется `result.json`, затем выводятся `wall_s`, `gpu_peak_mib` и
`eval_loss`. Для длинных строк создаётся файл `runs_exp/edge512.jsonl`. Полная матрица содержит
40 solution-only обучений, поэтому запускайте её на отдельной T4-сессии с достаточным временем.
Файлы экспериментов в репозитории остаются в `runs_exp/`; диагностические временные данные
создаются вне checkout. В конце будет вызван `scripts/t4_diag.sh`.

После отбора кандидата отдельно выполните полный прогон с базовой стороной и всеми правилами:

~~~bash
SOUP_X_ATTN_CKPT=1 SOUP_X_EXACT_RESID=1 SOUP_X_MERGE_VARIANTS=1 \
  python harness/run_task.py --repeats 2 --out runs_exp/final
python harness/check_rules.py --result runs_exp/final/result.json
~~~

Здесь второй checkpoint-вариант оценивается отдельной парой A-B-A-B в `t4_exp.sh`; одновременно
значения 1 и 2 у одного переключателя задать нельзя.

## Критерии принятия

Объединённый вариант можно считать кандидатом на включение по умолчанию только после T4-прогона,
в котором:

1. Полный `check_rules.py` показывает 10 из 10 проверок.
2. Доля времени наших ядер не ниже 6%, чтобы оставить запас над минимумом 5%.
3. Пиковая память не выше соответствующего прогона A без переключателей в той же сессии.
4. `eval_loss` хуже базы не более чем на 0,1%.
5. Ускорение устойчиво в обеих парах A-B-A-B и больше разброса между повторами.
6. Сохраняются шаги, токены каждого шага, entropy, mean token accuracy и row-loss rewind.

До выполнения этих условий новые настройки остаются экспериментами, выключенными по умолчанию.
