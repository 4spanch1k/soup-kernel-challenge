# Что предложили Claude и Codex и что оказалось лучше

Все цифры: Google Colab, Tesla T4, полный `harness/run_task.py` (база против решения).
Время в Colab плавает между сессиями (база 75-81 с), поэтому каждая строка сравнивается
со своей базой из того же прогона.

## Что вошло в `main` (итоговое решение)

| Часть | Автор | Файлы | Эффект |
|---|---|---|---|
| Chunked head + cross-entropy, онлайн-softmax | Claude (Codex делал ревью) | `ce_loss.py`, `head_patch.py` | память 14 345 → 8 427 МиБ |
| RMSNorm, RoPE | Claude | `rmsnorm.py`, `rope.py` | время 80,6 → 75,6 с (вместе с CE) |
| NF4-деквантизация (backward и forward matmul) | Claude | `nf4_dequant.py` | нужна для проверки 4 (доля ядер 2,9% → 4,97%) |
| Слитое «сложение + RMSNorm» | Claude | `add_rmsnorm.py` | время 75,7 → 65,8 с, память 8 427 → 6 321 МиБ |
| Слои без padding-строк (43% строк батча это padding) и слитые границы слоёв | Codex | `layer_tail.py` | время ×1,24 (75,9 → 61,1 с), доля ядер 10,4% |
| Общая fp16-таблица для embedding и головы | Codex | `embed16.py` | память 6 321 → 5 441 МиБ |

Итог: 76,4 → 63,5 с (×1,20), 14 345 → 5 441 МиБ (в 2,64 раза меньше), 10 из 10 проверок.
Повтор «как у жюри» (seed 2026, 2 прогона): 80,8 → 66,2 с (×1,22), 14 339 → 5 419 МиБ.

**Самое выгодное дали две вещи Codex:** пропуск padding-строк (больше всего по времени)
и общая fp16-таблица (больше всего по памяти). Основу (CE, нормы, NF4) сделал Claude;
без неё проверка 4 не проходила. Лучшее решение — их сочетание, ни одна половина
отдельно не победила бы.

## Что пробовали и отклонили (замерено на T4)

| Ветка | Идея | Автор | Результат |
|---|---|---|---|
| `q/varlen-attn` | Свой causal-attention по сэмплам на упакованных строках | Codex | без выигрыша (61,8 / 68,0 с против 66,9 / 68,3 с), память та же |
| `c2/fused4bit` | NF4-GEMM одним Triton-ядром | Codex | в 10-200 раз медленнее cuBLAS |
| `s/startup` | Сократить старт (Triton-компиляция 4,7 с) | Codex | остался только анализ; прогрев в потоке не используем (риск по правилам) |
| `w/load-phase` | Ускорить загрузку модели | Codex | экономия не больше 0,5 с |
| `l/lora-fuse` | Слить LoRA-путь | Codex | патч не срабатывал (не тот класс peft); микробенч не лучше |
| `m2/embed16-safe` | dtype-безопасная версия embed16 | Codex | безвредна, не влита |
| recompute MLP | Пересчёт активаций | Claude | +16% времени за −27% памяти: выключено |

Вывод: `main` — лучший из измеренных вариантов, остальные ветки проигрывают или не дают
выигрыша. Правило слияния новых идей: все 10 проверок, выигрыш ≥3% по времени или ≥5% по памяти,
доля ядер ≥6%, замер в той же сессии Colab, что и база.
